## 1. 产品定位与最高原则

CicloTrade 不是纯量化数据分析仪表盘，而是：

> 以真实量化数据、K 线、研究收据和风险合同为底座，由 AI 协助理解、比较、审议、生成草稿和复盘的金融控制台。

最终体验必须同时具备：

1. 真实金融数据与来源、时间、新鲜度、账户归属。
2. AI 的结构化协助、真实执行轨迹和可追溯引用。
3. CicloTrade 原创机器人、牛熊证据席、研究席和智能体等级素材。
4. 零基础用户能看懂的行动合同，以及高阶用户可展开的证据、K 线和风险工具。
5. 研究、官方验证模拟、个人模拟、券商实盘四个域严格隔离。

功能、文案、排版、组件、原创素材、响应式和全状态必须在同一模块波次交付。禁止“先把功能拼起来，以后再统一美化”，也禁止铺开多个只有一半的页面。

## 2. 参考作品的采用决策

### 2.1 完整采用并原创重做

- 午夜蓝黑连续工作区。
- 安静外围与单一发光核心。
- 决策中枢机器人作为 AI 状态载体。
- Market / News / Fundamental / Options / Signal / Risk / Report / Audit 工作流。
- 股票研究中心、紧凑研究行、微型趋势和真实队列进度。
- 牛熊双方与多研究席的证据审议结构。
- AI 会话、页面上下文、执行进度和记忆面板。
- 智能体能力阶段与成长路径。
- 细结构线、金属边缘、受控半透明表面、微型图形和状态点。

所有角色、图标、形态、背景和构图必须是 CicloTrade 原创，不复制参考作品的品牌、徽标、机器人轮廓、牛熊造型、席位或截图。

### 2.2 合并后增强

参考作品擅长展示“AI 正在工作”，CicloTrade 必须补齐其缺少的金融可信度：

- 每个结论包含来源、观察时间、数据状态和版本。
- 同时展示支持证据与反向证据。
- 明确最大风险、失效条件、复评时间和账户域。
- 迷你趋势不能冒充 K 线；正式研究保留 OHLC、成交量、周期和十字线。
- 97 只股票研究链显示已扫描、有效、过期、缺资料、排除和最近同步。
- AI 只生成个人模拟草稿，重新核价并由用户确认后才提交。
- 所有模拟订单进入持仓、监控、退出和逐单复盘闭环。
- 用户记忆可查看、编辑、删除、暂停和过期。

### 2.3 明确拒绝

- 无来源的“98.6% 成功率”“76 分胜率”“AI 在线率”等数字。
- 机器人冒充权威或替用户作出真实交易决定。
- 付费等级暗示预测更准、收益更高或风险更低。
- 粉紫蓝承担涨跌、买卖或风险语义。
- 牛熊赌场化、比分化、攻击化。
- Worker Log 暴露内部思维链、密钥、原始提示词或敏感日志。
- 随机曲线、伪 K 线、伪队列、伪实时状态和伪二维码。
- 每张卡都发光、玻璃墙堆叠、三层卡套卡和廉价霓虹。

## 3. 完整产品链路

```text
市场状态 / 报价 / K线 / 事件
  → 发现股票 / 筛选 / 研究候选
  → 13股稳定影子链 / 97股扩容链 / 业绩 / 期权研究
  → AI 结构化结论：行动类别 + 支持证据 + 反向证据 + 风险 / 失效
  → 用户打开完整 K线与证据核验
  → 创建预警或个人模拟草稿
  → 重新核价 + 组合风险闸门
  → 用户明确确认
  → 个人模拟订单 / 持仓 / 监控 / 退出
  → 逐单复盘 / 报告 / 待办
  → 用户可控偏好与记忆进入下一轮
```

研究结果永远不能自动变成个人模拟、官方策略、券商订单、Telegram 推送或实盘动作。

## 5. 全局 AI bounded context

AI 不是前端拼出的聊天框，必须新增独立领域与服务端合同。

### 5.1 核心模型

1. `ConversationSession`
   - 所有者、标题、页面上下文、创建/更新时间、归档与保留期。
2. `Message + ContentBlock`
   - user / assistant / system 状态、流式片段、结构化金融组件。
3. `AnswerContract`
   - 固定头部：账户域、research-only/个人模拟状态、数据时间和数据状态。
   - 方向性研究：结论 → 引用与时间 → 支持证据 → 反向证据 → 风险/失效 → 下一步。
   - 中性问题：事实 → 限制 → 未知项 → 可验证下一步，不强行生成看多/看空。
   - 数据不足时允许明确拒绝结论；百分比或评分只能来自已定义、可校准且可解释的指标。
4. `Citation`
   - 新闻、公告、财报：展示公开发布者、文档、发布时间、观察时间和链接。
   - 行情与分类数据：仅展示批准的用户侧来源标签、报价时间和数据状态。
   - 内部 vendor、connector、凭据、路由和原始日志只进入服务端审计，禁止进入 API、DOM 或 AI 回答。
5. `ToolExecutionTrace`
   - queued / running / succeeded / partial / failed / cancelled / blocked；仅展示可公开的结构化事件。
6. `EditableMemory`
   - 市场、周期、风险和展示偏好；逐条编辑、删除、暂停和到期。
7. `PageContextSnapshot`
   - 当前路由、股票、市场、周期、账户、新鲜度和权限；不抓原始 DOM。
8. `PaperDraftHandoff`
   - 草稿 ID、股票、方向、订单类型、数量/价格、报价时间、风险摘要和来源会话。
9. `PermissionPolicyGate`
   - read、read_sensitive、create_draft、save_preference 等显式能力；broker submit 对 AI 永久拒绝。
10. `RetentionDeletionAudit`
    - 会话/记忆删除、保留策略和审计收据。
11. `StreamingStatus`
    - SSE/WebSocket 断线、重连、取消、超时和部分成功。
12. 版本与评估收据
    - prompt/model/tool 版本可审计，但不展示内部思维链。

### 5.2 AI 回答版式

金融回答必须整齐、可扫描，但根据问题类型选择模板：

1. 固定头部：账户域、research-only/模拟状态、数据时间和数据状态。
2. 方向性研究：一句话结论、关键数字、支持证据、反向证据、风险/失效、下一步。
3. 中性解释：事实、限制、未知项和验证路径。
4. 数据不足：明确说明不能下结论、缺少什么、何时复评。

可选操作只能是：打开 K 线、比较股票、保存研究、建立预警、前往个人模拟核价。AI 不显示“立即下单”。

## 6. 原创角色与素材系统

### 6.1 Ciclo Core / 循环中枢

- 不对称圆角六边形头部。
- 单条 C 形光学面罩。
- 胸口烟熏蓝晶“证据核心”。
- 两条错位陀螺证据轨道。
- 石墨陶瓷、雾面钛金属与烟熏晶体。
- 无武器、无儿童玩具感、无夸张表情。

状态：neutral、processing、locked/offline。  
用途：`/paper`、AI 助手、研究生成、工作流汇总、多智能体裁决。  
市场/K 线页只能使用 `32–48px` 状态头像，不得抢占图表。

### 6.2 牛熊证据席

- 牛：多头证据倡议者；牛角由上扬 C 形轨道构成。
- 熊：风险与反例审查者；肩甲为收拢的防护结构。
- 两者相同高度、比例、材质和视觉权重。
- 绿色和红色只用于很小的金融语义状态区。
- 桌面并列，手机改为“看多 / 看空 / 结论”页签。

### 6.3 四类研究席

- 市场结构席：价格轨迹环与波形天线。
- 基本面席：账本鳍片与财报棱镜。
- 新闻宏观席：广播环与事件扫描器。
- 风险席：盾形光圈与缺口检测器。

每席为独立素材，状态、名称、进度和日志由代码渲染。

### 6.4 五级智能体形态

- L0 Kernel：单证据核心与未闭合轨道。
- L1 Scout：感知面罩与基础传感翼。
- L2 Analyst：双数据环与证据仓。
- L3 Orchestrator：多轴轨道与研究节点接口。
- L4 Guardian：证据护盾、风险闸门与审计环。

等级表示资料、授权、功能和风险治理完整度，不表示预测准确率或收益能力。

### 6.5 状态与金融图形

原创状态素材：Empty、Data gap、Error、Locked、Stale、Offline、Invalidated。  
代码化微型图形：`MiniCandles`、`MiniTrend`、`SegmentRail`、`StateWave`、`StatusOrbit`、`CoverageBar`。

所有文字、价格、日志、按钮、标签和真实金融图表必须由 HTML/SVG/Canvas 渲染，不能烘进图片。

### 6.6 素材性能

- 3D 角色预渲染为 WebP/AVIF，不引入实时 WebGL。
- 首屏新增位图预算：桌面 `<=600KB`，手机 `<=280KB`。
- Hero `<=260KB`，头像 `<=30KB`，牛熊单张 `<=140KB`。
- `srcset`、懒加载、按路由加载；不一次下载全部角色包。
- 禁止 GIF、自动播放视频和无限循环大动画。
- 深浅主题分别渲染，禁止滤镜反色。

第一轮概念图只用于美术方向确认，不能直接作为生产资产；最终文件必须记录稳定文件名、版本、源提示、尺寸、主题、SHA 和使用页面。

生产素材清单还必须记录：生成工具/模型、授权条款、提示词版本、人工修改、参考图隔离方式和许可收据。上线前由未参与生成的 reviewer 做独立相似度审查；品牌徽标、机器人轮廓、牛熊造型、席位构图和背景不得与参考作品形成可识别复制，参考截图不得进入生产包。

## 9. 页面迁移

### `/today`

左侧账户与今日待办；中央 AI 执行轨和行动合同；右侧持仓风险与数据健康。内部可复用 recommendations、portfolio、performance、alerts 和 risk DTO，但 `recommendations` 只是内部技术名称。用户界面必须按账户域显示“研究行动”“官方验证”“个人模拟”或“实盘”，不得把所有域统一包装成“推荐”。

### `/discover`

股票搜索、筛选、97 只股票覆盖、研究行、真实 MiniTrend/MiniCandles、证据完整度和生成状态。链路：候选 → 研究 → K 线 → 预警/模拟预填。

### `/research`

现有完整 K 线保持第一视觉。AI 只进入右侧 Inspector 的结论、牛熊证据、引用、风险和预警标签。

### `/paper`

v1 固定为 USD 10,000 个人美股模拟；期权模拟明确后置。完整链路为 AI 草稿 → 服务端报价证明 → 订单预览 → 服务端风险证明 → 用户确认 → 幂等提交 → 明确收据/未知结果恢复 → 持仓、盈亏、取消和复盘。AI 永远没有 submit capability。

否决条件：

- 报价证明必须绑定股票、价格、报价时间、市场时段、账户版本和有效期；stale、闭市或证明不匹配时 fail-closed。
- 风险证明必须覆盖购买力、单笔最大亏损 USD/%、持仓与行业集中度、当前回撤、财报/事件跳空风险和流动性。
- 修改股票、方向、订单类型、数量、价格或有效期后，原报价和风险证明立即失效。
- 草稿、报价证明、风险证明、用户确认、提交请求和最终收据必须是不同对象。
- 幂等键、重复点击、并发提交、响应丢失和未知提交结果不得产生重复订单或重复占用购买力。

### `/portfolio`

官方验证模拟域。事件 → 执行 → 结果 → 风险 → 证据，不能与个人模拟余额或券商实盘混合。

### `/reports`

13 股稳定链和 97 股扩容链并列但合同隔离。显示 WAIT / research-only / freshness / history / invalidation，不冒充买卖推荐。

### `/earnings`

事件快照、概率区间、支持/反向证据、有限风险结构、结果与校准。统计不得冒充个人收益。

### `/lab`

DATA → STRATEGY → BACKTEST → RISK → REPORT。后端已有受开关保护的正规回测队列；Web 必须接真实 job、进度、取消和制品 API。未启用时显示 locked，禁止伪造 AI 回测。

### `/notifications`

Telegram 绑定、验证、授权和偏好使用真实 WorkflowRail；投递结果/日志 API 未接入前明确显示“尚未接入”。

### `/trade`

## 10. 响应式

- 1920：sidebar `216px`，AI rail `360px`；三栏约 `300 / minmax(720,1fr) / 340`。
- 1440：sidebar `216px`，AI rail `320px`；三栏约 `250 / minmax(520,1fr) / 280`。
- 1024：sidebar `184px`；AI 改 `360px` overlay；主页面最多两列。
- 768：icon rail `64px`；单主列，Inspector 进入 Drawer/Sheet。
- `<=760`：底栏 `58px + safe-area`；AI 全屏；机器人缩为 `56–72px` 状态带。
- 390：研究单列；牛熊三页签；工作流纵向 Accordion 或横向步骤条；成长轨横向滑动。
- 横屏 `<=980×560`：隐藏大机器人与非关键侧轨，Inspector Sheet `<=70%` 高度，AI 不覆盖活动 K 线。
- 手机 AI 使用 `100dvh`、safe-area、软键盘避让、焦点圈定/恢复和 body scroll lock；禁止会话区与页面主体形成难以控制的嵌套滚动。
- Sheet、Drawer 和输入法不得覆盖活动 K 线、个人模拟确认按钮或风险拒绝原因。

## 14. 验收门

每个页面必须同时通过：

1. 功能与失败路径。
2. 安全与账户域隔离。
3. 独立 UI finish gate。
4. 原创素材与授权检查。
5. 深/浅色、简/繁体。
6. 1920、1440、1024、768、390 和横屏。
7. 键盘、焦点、44px 触控、reduced-motion。
8. 性能、懒加载、无控制台错误和无横向溢出。
9. 登录/欢迎零可见变化。

最低产品证据：

- 每个 AI 回答有账户域、来源/时间和数据状态；方向性结论还必须有反向证据、风险和失效，中性问题不得被强行包装成方向判断。
- 每个“正在运行”有真实状态源。
- 每个小 K 线是真实 OHLC；折线明确叫趋势。
- 每个写操作由用户明确确认。
- 每个素材是 CicloTrade 原创。
- 每页最多一个大角色和一个渐变 CTA。
- K 线、风险和真实证据永远优先于机器人。

### 14.1 客观性能门

测试环境必须记录浏览器版本、视口、CPU/网络节流、构建 SHA 和资源清单。最低门：

- 生产 RUM 目标：p75 LCP `<=2.5s`、CLS `<=0.1`、INP `<=200ms`。
- 发布前移动实验室：4× CPU + Slow 4G 下 LCP `<=3.0s`、CLS `<=0.1`、TBT `<=200ms`。
- 单路由新增压缩后 JS `<=60KB`、CSS `<=20KB`；不得为单个角色引入 3D 引擎。
- 首屏素材继续遵守桌面 `<=600KB`、手机 `<=280KB`；新字体不得阻塞首屏。
- 路由打开前 5 秒累计 long-task 时间 `<=200ms`，单个任务不得超过 `100ms`。
- AI 连续流式会话 30 分钟后内存增长 `<=50MB`，消息列表必须窗口化或分页；空闲动画在参考设备单标签 CPU 目标 `<5%`。
- reduced-motion 下无轨道循环、脉冲和自动滚动；功能状态仍完整可见。

## 15. 服务器与性能升级决策

先采用预渲染角色、按路由加载、轻量 SVG/CSS 动效和 CDN/缓存策略。实现后以首屏资源、LCP、内存、CPU、并发和 API 延迟为依据决定是否升级服务器。

若素材优化后仍由服务器资源成为明确瓶颈，可升级；不以服务器升级代替图片压缩、缓存、懒加载、查询优化或静态资源分发。
